# Exploration: dialogs and administration

Run all red scripts: `.venv/bin/python -m pytest -p walks.conftest .scratch/html-front-end/explore/dialogs-and-administration/test_explore_dialogs_and_administration.py -q`
Screenshots: `.scratch/html-front-end/walks/test-explore-*.png` (git-ignored, regenerated by the run).

## Tried
- Menu: open by Enter, focus to first item, Escape closes and returns focus, Tab through items (menu stays open), ArrowDown does nothing
- Rename dialog: empty, duplicate, duplicate by case (refused), own name unchanged (closes), 400-character unbroken name, Tab and Shift+Tab cycle (trapped), Escape with an error showing, focus return to the menu button after save and cancel
- Delete dialog: long unbroken name, delete the first watchlist (lands on the next, focus on menu button), delete the last (see defect 2)
- New watchlist: 3000-character name, markup name, bidi-control name, padded name, emoji (all created; no overflow of the page), Enter pressed twice quickly (one watchlist)
- Stale state: watchlist deleted in a second tab, then rename and delete from the first (stated "There is no watchlist 2.", dialog stays open, cancel works)
- Server stopped mid-rename ("Failed to fetch" shown in the dialog, can be retried)
- Full recheck, Rename and Delete while a check is running (slow stand-in)
- First-use screen: content, no tabs, no menu
- run.py: second start same path, relative path from another folder, nonexistent folder, port taken, port out of range, stale lock after kill -9, symlinked database path
- 1440 x 900 for all; the red scripts also run at 1024 x 768

## Odd, not wrong
- The ⋯ menu stays open on Tab and has no arrow-key movement (Tab works; Escape and outside click close it).
- A very long watchlist name fills the whole sidebar height with one wrapped name.
- Saving Rename with the unchanged name closes silently.
- Each redraw of the header adds another document click listener for the menu (a small leak, no visible effect).
- A name made visually identical with Unicode lookalikes or bidi controls is accepted.
- New watchlist from the sidebar leaves the user on the current view with the new one only in the sidebar.
