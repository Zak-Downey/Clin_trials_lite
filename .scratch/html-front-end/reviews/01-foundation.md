## Blocking

1. **The server answers any web page the analyst visits; nothing checks Host or Origin.** Any website open in the analyst's browser can send requests to `http://127.0.0.1:<port>/`. A DNS-rebinding page (its own hostname re-pointed at 127.0.0.1) can then read the replies as same-origin: today that is every watchlist name, every watched NCT ID and its changes. Once a POST route lands (tickets 03, 04, 08, 13), a plain cross-site form POST (`text/plain`, no preflight) reaches the handler. The analyst is the one exposed. Story 101 and ADR 0003 promise that "nobody else can reach it". The fix belongs in the dispatcher every route goes through, so landing it now costs one place and landing it later costs a retrofit under live writes. That means refusing a `Host` that is not `127.0.0.1:<port>` / `localhost:<port>`, and on writes refusing a foreign `Origin` and any `Content-Type` other than `application/json`. No later ticket owns this (I grepped the issues for origin, host header, rebind and csrf). | `webapp/server.py:58-80` (`_dispatch`) | **Reproduced**: `GET /api/watchlists` with `Host: evil.example:<port>` and `Origin: http://evil.example` answered 200 with the watchlist body. A `POST` with `Origin: http://evil.example` and `Content-Type: text/plain` was dispatched (405 only because no POST route exists yet). | blocking

2. **A folded history move carries one change ID, so reviewing "the IDs shown" leaves the qualifier change unreviewed for good.** `history()` takes `id` from the value's change row alone. When a date and its type move in the same check (the case the spec calls the most informative one), the type row's ID never reaches the caller. Review by change ID (ticket 04, "marks exactly those") will then mark the date and leave `primaryCompletionDateType` unreviewed. The trial stays in Needs review with nothing on its Changes tab to clear. The same ID-less fold feeds `reviewed` (taken from the value row only). The shape to fix is the move's: `ids: [...]` (every row it folds), with `reviewed` true only if all are. That is cheap now and expensive once ticket 04's review endpoint and ticket 05's History consume `id`. | `monitor.py:1113-1121`, `diff.py:fold_moves` | **Reproduced**: a primaryCompletionDate change (id 1) and a primaryCompletionDateType change (id 2) in one check. `history()` returned `[('primaryCompletionDate', 1)]`, and id 2 appears nowhere. The test `test_history_moves_carry_the_change_id_and_the_check` uses a single unqualified field, so it cannot see this (its own `Lacks:` line says so). | blocking

## Design

3. **The queue and the changes endpoint count the same changes differently.** For the same two rows as in finding 2, `needs-review` reports `change_count: 1` / `field_changes: 1` (folded per check), while `/api/trials/<id>/changes` returns 2 rows (unfolded, no qualifier fold at all). The spec's "6 unreviewed field changes" heading and the trial page's list will disagree whenever a qualifier moved. Choose one unit (the folded move) and have both endpoints return it, with its IDs. `/changes` is the endpoint ticket 04 builds the review action bar on. | `webapp/api_trials.py:14-33` vs `monitor.py:needs_review` (`change_count`) | **Reproduced**: same probe, queue `{'trials': 1, 'field_changes': 1}` against 2 rows from `/changes`. | design

4. **One database, two servers: nothing stops a second `python run.py`.** ADR 0003 rests on "one server process serializes every write", and the spec on "all database writes go through one connection guarded by a lock". Each `run.py` picks its own free port, so starting the app twice (a second terminal, or a forgotten window) gives two processes, two connections and two lock domains over one `monitor.db`. Once checks run on a background thread, two checks of the same watchlist can run at once. The server enforces one check at a time per watchlist, so story 19 holds only within a single process. A lock file beside the database, or a stored "server at port N" record that the second start reads and opens the browser on, belongs in the foundation. | `run.py:109`, `webapp/server.py:make_server` | **Reproduced** in-process: `make_server(db)` twice on the same path, and both bound and served. | design

## Sweep

5. **Every handler must remember to take `ctx.lock`; nothing enforces it.** The connection is opened `check_same_thread=False` under `ThreadingHTTPServer`, and safety is the convention "used ... always under self.lock". Every later API module adds handlers, and one that forgets the `with ctx.lock:` races on a shared sqlite3 connection with no test able to see it. Take the lock in `_dispatch` around the handler call, or pass handlers a locked-connection accessor instead of `ctx.conn`. Also decide now whether the background check (ticket 03) holds the lock across registry fetches. If it does, story 18 ("keep reading while checking") fails. | `webapp/server.py:22-30, 69`; `webapp/api_*.py` | inferred from code | sweep

6. **The page renders times in the browser's zone and labels them with the server's.** `when()` formats `new Date(time.iso)` with `toLocaleString` (browser zone) and appends `time.zone` (the server process's zone). On one machine they usually agree. They will disagree as soon as the walk helper (ticket 02) starts the server with `TZ` set for determinism and Chromium runs in another zone: a walk asserting "Last checked <local time>" then reads a time in one zone labelled as another. Format the wall-clock already in `iso`, or pass `timeZone` explicitly. | `webapp/static/api.js:15-19` | inferred | sweep

7. **The stand-ins table is still empty, and the API seam leans on stubs that have no row.** The `api` fixture is the seam every `tests/test_api_*.py` will use. It injects `make_fetcher`/`make_finder` stubs for the registry, while `run.py` passes neither, so production runs with `fetch=None, find=None`. The `make_server` docstring nonetheless says "real ones by default". The earlier review's Note 4 left the `None` defaults because no endpoint uses them yet. That still holds for this diff. What it did not cover is the docstring describing a contract that is not there, and the missing rows for "stub fetcher/finder for the ClinicalTrials.gov client" and "in-process `make_server` for `run.py`". | `webapp/server.py:89-90`, `docs/agents/local/repo.md` (Stand-ins table) | read | sweep
