# This repo

What is particular to this repo. Every line below is a fact of this repo; a line left blank is a gap an agent will trip on.

## Commands

- **Unit suite.** `.venv/bin/python -m pytest -q`, run from the repo root (tests in `tests/`). Under `checks.py` its output goes to `.checks/unit.txt`.
- **Walk suite.** `.venv/bin/python walks/run_walks.py` (four workers, then each failure alone; output under `.scratch/<feature>/walks/walks-run.txt`). One walk alone: `.venv/bin/python -m pytest walks/test_needs_review_walk.py -q`. Under `checks.py` the check is named `walks`.
- **Outline a module.** `grep -n '^def \|^class ' <file>.py`
- **Every check.** `python3 checks.py` runs four checks, cheapest first, stopping at the first red: `patterns` (no file matches a forbidden pattern), `escapes` (the defect log reads, and each new line names its check), `unit` and `walks`; the list is at the top of `checks.py`. A full run takes about four minutes. Each check is stopped and called red at its time limit: `patterns` and `escapes` 1 minute, `unit` 3, `walks` 8, so a whole run ends within 13 minutes: give it a fifteen-minute timeout or run it in the background. The limits are this product's own, set at about three times a normal run (the unit suite takes about 1.0 minute, the walks about 2.4); a product whose suites grow raises them on purpose, in `CHECKS` and in the test that pins them (`tests/test_checks.py`). Each check's output is a file under `.checks/` (git-ignored), and each run appends one line to `.checks/runs.jsonl`.

## Walks

- **Tooling.** Playwright for Python with Chromium (`requirements-dev.txt`; once: `.venv/bin/python -m playwright install chromium`), run by pytest in `walks/`, outside the unit folder (`pytest.ini` points the unit suite at `tests/`). The pages are exercised only by the walks; the unit suite tests the API and the Python modules, with no browser.
- **Helpers.** `walks/helper.py` (the app in a subprocess on a free port over a fresh temporary database, the stand-in registry, the guards: console error, page error, failed or foreign request, sideways scroll; seeded data `seed_queue`) and `walks/conftest.py` (fixtures `make_app`, `make_walk`, `registry`, `viewport`; a walk whose guards tripped is reported FAILED). `walks/standin_registry.py` is the stand-in registry; `walks/serve.py` starts the app against it. A walk is `walk = make_walk(make_app(seed=...))`, then acts through `walk.page` by role and name.
- **Walk output.** `.scratch/<feature>/walks/` (git-ignored): `<walk>-NN-<step>.png`, a `-final` shot of every failed walk, and `walks-run.txt`.
- **Recording a walk.** `WALK_RECORD=<folder>` records each walk's page as `<folder>/<walk>.webm`, slowed so a person can follow it (`WALK_SLOW_MO` milliseconds a step, default 350). `python3 handover.py <feature>` uses it to record, for the hand-over page, the walks a build added or changed (a test function in `walks/test_*.py` with a changed line of its own) that its `hand-over.json` lists under `walk_through`, each once at 1440 x 900; a build that changed none gets the acceptance walk. Unset, nothing is recorded and nothing is slowed.
- **Shared client plumbing.** `webapp/static/app.js`, `webapp/static/focus.js`, `webapp/static/api.js`, `webapp/static/style.css`, `walks/helper.py`, `walks/conftest.py`, `walks/standin_registry.py`, `walks/serve.py`. A change to one runs the whole walk suite.
- **Areas.** The shell and sidebar; Needs review; All trials; New matches; Summary; the trial page; Find trials.
- **Viewports.** 1440 x 900 and 1024 x 768 (every walk runs at both); the acceptance walk (`walks/test_acceptance_walk.py`) runs at both in Chromium and at 1440 x 900 in Playwright's WebKit (`.venv/bin/playwright install webkit` once; it is part of the walks check). The browser runs in Asia/Tokyo and the server in America/New_York, so a time shifted into the browser's zone shows.
- **Agents running browsers at once.** 3 (a suite run uses four workers; the runner re-runs a failure alone, so load-only flakes show as such: each run appends the walks that were red under load and green alone to `.scratch/<feature>/walks/flaky.jsonl`, and the hand-over page lists each one for the owner and says when that record is missing for the build's last run of the walks).
- **Not checkable by a walk here.** Wording and legibility, Safari, real hardware, the live registry (`walks/fidelity_check.py` is by hand).

## Running a walk

Write `walk = make_walk(make_app(seed=helper.seed_queue))`, `walk.page.goto(app.url)`, act by role and name, assert on what is drawn, `walk.shot("step")`. The stand-in registry's switches are `registry.set("revise")` and so on (its control endpoint, never the app). A new guard or helper change runs `walks/test_walk_guards.py`, which runs deliberately broken pages in `walks/broken/`. A walk that proves an error response declares it first with `walk.expect(status, path)`; the guards then treat that response as expected, and fail the walk if it never comes.

A script outside `walks/` (a walker's or reviewer's, under `.scratch/<feature>/findings/scripts/`) runs from the repo root with `WALK_FEATURE=<feature> .venv/bin/python -m pytest -p walks.conftest <script> -q`; a unit one with `-p tests.conftest`. The `-p` loads the fixtures and the hook that fails a walk whose guards tripped; do not copy or import the fixtures by name instead, because that leaves the hook out.

## What checks the stand-ins

- **The registry stand-in's filters.** Nothing narrows by phase, status or date, so `walks/test_find_trials_walk.py` asserts the parameters in the stand-in's recorded requests.
- **The patched `time.sleep`.** The unit tests skip the pause between registry calls; `walks/test_check_walk.py` runs a check against the stand-in's `slow` switch with the real sleep.

## CI

- **Workflows.** One: `.github/workflows/checks.yml`, with one job named `checks` (the status check the owner requires on `main`). It runs when a pull request is opened, pushed to, reopened or marked ready for review (drafts included, no path filter), and by hand; never on a push. It makes the repo's `.venv` with Python 3.13, installs both requirements files and Playwright's Chromium and WebKit (WebKit for the acceptance walk, part of the `walks` check), and runs the full `python3 checks.py` with no check named. Its limit is 20 minutes; a newer run on the same branch cancels the older one, and on red the files under `.checks/` are uploaded with the run. Before the checks, a notice in the run's summary lists the files the pull request changes that judge it (`.github/workflows/`, `checks.py`, `.claude/settings.json`, `pytest.ini`) and how many tests it removes (`.github/workflows/judge_notice.py`); it never fails the run. A pull request runs its own branch's copy of the workflow, merged with `main`, so the notice is for the owner to read, not a guard. `tests/test_workflow.py` holds what the file says, and that this line names every workflow file there is; nothing here runs it on GitHub. The old Pages publish workflow is retired.
- **Local hooks.** None. `python3 checks.py` is run by hand and by `/implement-spec` after every ticket.
